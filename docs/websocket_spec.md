# Спецификация протокола WebSocket — YolYolakay Platform

## 1. Подключение и аутентификация

**URL подключения:**  
`wss://api.yolyolakay.com/ws` (или `ws://localhost:8080/ws`)

**Аутентификация:**
Передается действующий JWT Access Token одним из двух способов:
1. Через заголовок HTTP Upgrade: `Authorization: Bearer <access_jwt>`
2. Через query-параметр: `wss://api.yolyolakay.com/ws?token=<access_jwt>`

**Служебные сообщения (Keep-Alive):**
* Сервер периодически отправляет стандартные кадры WebSocket `Ping`. Клиент должен отвечать кадрами `Pong` (в большинстве WS-клиентов обрабатывается автоматически).
* Лимит на частоту отправки сообщений: 5 сообщений в секунду (burst: 5). При превышении лимита пакет отбрасывается без разрыва соединения.

---

## 2. Формат сообщений

Все сообщения передаются в формате JSON с базовой структурой:
```json
{
  "event": "название_события",
  "data": { ... }
}
```

---

## 3. Входящие события (Клиент ➔ Сервер)

### 3.1. `send_message` — Отправка сообщения в чат
Отправка текстового сообщения собеседнику.

```json
{
  "event": "send_message",
  "data": {
    "receiver_id": "11111111-1111-1111-1111-111111111111",
    "ride_id": "22222222-2222-2222-2222-222222222222",
    "reply_to_id": "33333333-3333-3333-3333-333333333333",
    "content": "Здравствуйте! Где вы сейчас находитесь?"
  }
}
```
* **Параметры:**
  * `receiver_id` *(string UUID, обязательный)*: ID получателя.
  * `ride_id` *(string UUID, опциональный)*: ID связанной поездки.
  * `reply_to_id` *(string UUID, опциональный)*: ID сообщения, на которое дается ответ.
  * `content` *(string, обязательный)*: Текст сообщения.

---

### 3.2. `mark_as_read` — Отметка сообщений как прочитанных
Уведомляет сервер о прочтении входящих сообщений.

```json
{
  "event": "mark_as_read",
  "data": {
    "message_ids": [
      "33333333-3333-3333-3333-333333333333",
      "44444444-4444-4444-4444-444444444444"
    ]
  }
}
```

---

### 3.3. `typing` — Индикатор набора текста
Отправляется, когда пользователь печатает ответ.

```json
{
  "event": "typing",
  "data": {
    "receiver_id": "11111111-1111-1111-1111-111111111111"
  }
}
```

---

### 3.4. `subscribe_ride` — Подписка на GPS-трекинг поездки
Пассажир подписывается на real-time обновления координат машины в активной поездке.

```json
{
  "event": "subscribe_ride",
  "data": {
    "ride_id": "22222222-2222-2222-2222-222222222222"
  }
}
```

---

### 3.5. `location_update` — Передача текущих координат водителем
Только для водителя текущей активной поездки.

```json
{
  "event": "location_update",
  "data": {
    "ride_id": "22222222-2222-2222-2222-222222222222",
    "lat": 41.311081,
    "lon": 69.240562
  }
}
```

## 4. Исходящие события (Сервер ➔ Клиент)

### 4.1. `new_message` — Новое сообщение
Приходит получателю и на другие устройства отправителя (эхо-подтверждение).

```json
{
  "event": "new_message",
  "data": {
    "id": "33333333-3333-3333-3333-333333333333",
    "sender_id": "11111111-1111-1111-1111-111111111111",
    "receiver_id": "22222222-2222-2222-2222-222222222222",
    "ride_id": "22222222-2222-2222-2222-222222222222",
    "reply_to_id": "00000000-0000-0000-0000-000000000000",
    "content": "Здравствуйте! Где вы сейчас находитесь?",
    "status": "sent",
    "created_at": "2026-08-23T23:10:00Z",
    "updated_at": "2026-08-23T23:10:00Z"
  }
}
```
* `created_at` / `updated_at` всегда передаются в формате ISO8601 (UTC).

---

### 4.2. `messages_read` — Собеседник прочитал сообщение
```json
{
  "event": "messages_read",
  "data": {
    "message_id": "33333333-3333-3333-3333-333333333333",
    "read_by": "22222222-2222-2222-2222-222222222222"
  }
}
```

---

### 4.3. `typing` — Собеседник печатает
```json
{
  "event": "typing",
  "data": {
    "sender_id": "11111111-1111-1111-1111-111111111111"
  }
}
```

---

### 4.4. `driver_location` — Обновление геопозиции автомобиля
Рассылается всем пассажирам, подписанным на `subscribe_ride`.

```json
{
  "event": "driver_location",
  "data": {
    "ride_id": "22222222-2222-2222-2222-222222222222",
    "lat": 41.311081,
    "lon": 69.240562
  }
}
```

---

### 4.5. `ride_status_changed` — Изменение статуса поездки
```json
{
  "event": "ride_status_changed",
  "data": {
    "ride_id": "22222222-2222-2222-2222-222222222222",
    "status": "in_progress",
    "updated_at": "2026-08-23T23:10:00Z"
  }
}
```
Статусы: `draft` | `active` | `in_progress` | `completed` | `canceled`.
